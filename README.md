# Lung Cancer Survival-Status Classification

An educational data-analysis and machine-learning project developed for the COM692 module. It prepares tabular lung-cancer records and compares three binary classifiers that predict the recorded `survived` outcome:

- Logistic regression
- Decision tree (CART)
- Random forest

> **Important:** Despite the repository name, this is survival-status classification, not time-to-event survival analysis. It does not use censoring or models such as Kaplan-Meier or Cox regression.

## What this project demonstrates

- Data validation, deduplication, and missing-value handling
- Reproducible feature engineering
- Stratified train/test splitting
- Training-only imputation, encoding, scaling, and SMOTE
- Model comparison with accuracy, kappa, sensitivity, specificity, ROC curves, and AUC
- Clear documentation of limitations and responsible use

## Run locally

1. Install R 4.2 or newer.
2. In R, run `source("packages.R")` once to install dependencies.
3. Place an authorised copy of the dataset at `data/raw/Lung Cancer.csv`.
4. From the repository root, run:

```r
source("analysis.R")
```

You can also pass a different dataset path:

```text
Rscript analysis.R "C:/path/to/Lung Cancer.csv"
```

The script creates evaluation tables and figures in `outputs/`.

## Methodology

The target is normalised to the factor levels `No` and `Yes`, with `Yes` treated as the positive class. Records are split 80/20 using stratification. Imputation values, factor levels, one-hot encoding, and scaling parameters are learned from the training set only. SMOTE is then applied only to the transformed training data. The untouched test partition is used for the final comparison.

This portfolio version improves the original academic script by removing a computer-specific working directory, separating dependency installation from analysis, validating inputs, and preventing information from the test set leaking into preprocessing.

## Limitations and responsible interpretation

- This is a retrospective classification exercise, not a clinical prediction tool.
- Dataset provenance, sampling design, and external validity must be established before interpreting results.
- Synthetic oversampling can improve class balance but may not improve real-world generalisation.
- A single held-out test set is useful for coursework but does not replace external validation.
- Accuracy alone can be misleading for imbalanced outcomes; sensitivity, specificity, and AUC are included for context.
- No medical decisions should be based on this project.
